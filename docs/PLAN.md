# Life Hub — план проєкту

Life Hub об'єднує планер задач, фінанси і CRM в одному Telegram Mini App з ботом; той самий сайт працює й у браузері.

Це адаптація початкового плану під наявний репозиторій «planerok»: стек лишається Python + PostgreSQL + Docker, дизайн Mini App лишається поточним («Dark Neon Purple», див. `.cursorrules`).

## Рішення

- **Стек:** FastAPI + aiogram 3 + SQLAlchemy 2.0 (async) + Alembic + APScheduler; фронт — Next.js 15 + Tailwind. Хостинг — Docker на власному сервері (planer.pp.ua), статична копія фронту на GitHub Pages.
- **Мова інтерфейсу:** лише українська.
- **Базова валюта:** EUR для всіх користувачів (поле `base_currency` у профілі на майбутнє).
- **Спільний доступ:** у кожного користувача свої особисті простори (планер і фінанси) плюс спільні простори за запрошенням.
- **Порядок:** спершу допилюємо планер, потім фінанси, далі решта.

## Принципи

- Один вхід: Telegram Mini App + бот; сайт у браузері як запасний варіант.
- Внутрішній ID користувача; Telegram — лише один зі способів входу (`auth_identities`).
- Приватне за замовчуванням, спільне за вибором (простори з ролями).
- Швидкий ввід скрізь: один рядок у Mini App і те саме повідомленням боту, один парсер.
- Гроші — цілі числа (центи), оригінальна валюта + курс на дату операції.
- Експорт усіх даних у CSV/JSON у будь-який момент.

## Модель даних

Усі дані належать простору (`space_id`), простір — користувачам через `space_members`.

| Таблиця | Ключові поля | Нотатки |
|---|---|---|
| `users` | id, display_name, locale, theme, accent_color, base_currency, timezone | внутрішній ID |
| `auth_identities` | user_id, provider (`telegram`, `email`), external_id | кілька способів входу |
| `spaces` | id, name, color, icon, kind (`personal`, `shared`) | особистий простір створюється автоматично |
| `space_members` | space_id, user_id, role (`owner`, `editor`, `viewer`) | на ній тримається вся ізоляція |
| `tasks` | space_id, created_by, title, status, priority, due_at, recurrence_id | статуси: backlog, todo, doing, done |
| `recurrences` | rule (RRULE), streak_current, streak_best | повторювані задачі та звички |
| `notification_prefs` | user_id, digest_time, enabled_types | ранковий дайджест |
| `accounts` | space_id, name, currency, kind (`card`, `cash`, `savings`) | фінанси |
| `buckets` | space_id, name, kind (`base`, `personal`, `business`, `capital`, `sinking`) | «чиста база» |
| `transactions` | account_id, bucket_id, category_id, amount_cents, currency, fx_rate, base_amount_cents, occurred_at, is_one_off, tags | цілі числа |
| `split_rules` | space_id, name, rules (bucket_id → %) | сума = 100 |
| `sinking_funds` | bucket_id, target_cents, due_date, monthly_cents | monthly рахується автоматично |
| `contacts`, `deals`, `invoices` | space_id, stage, amount_cents, due_date, linked_task_id | CRM |

Правила: суми лише в центах; «чиста база» = транзакції кошика `base` без `is_one_off`; кожна таблиця має `created_at`, `updated_at`, `deleted_at`; дати в UTC, часовий пояс користувача — у профілі (за замовчуванням `Europe/Vienna`).

## Ізоляція даних

Кожен запит API фільтрується через членство в `space_members` (спільна залежність у `app/api/deps.py`). На кожну таблицю зі `space_id` — тест, що чужий користувач не бачить і не змінює чужі рядки. Postgres RLS можна додати пізніше як другий рівень захисту.

## Етапи

Кожен етап закінчується робочою версією.

0. **Фундамент.** `docs/PLAN.md`, `CLAUDE.md`, кореневий `.env.example`. Готово, коли документи в репо.
1. **Користувачі та простори.** `users`, `auth_identities`, `spaces`, `space_members`; міграція наявних задач (Telegram ID → внутрішній користувач з особистим простором); вхід через initData створює користувача. Готово, коли: два акаунти не бачать даних один одного, спільний простір бачать обидва (тести проходять), а наявні задачі не загубились.
2. **Планер (донабудова).** `#простір` у quick add, `@дата`, статуси backlog/todo/doing/done, повторювані задачі зі streaks, Today-вид, ранковий дайджест у заданий час. Готово, коли: `Звіт #Бізнес !high @завтра` створює задачу в потрібному просторі з потрібною датою, дайджест приходить вчасно.
3. **Спільний доступ і види.** Запрошення за посиланням, ролі, Kanban, зведений вид «Усі простори». Готово, коли: друга людина приєднується за посиланням і бачить лише спільний простір і свої дані.
4. **Фінанси.** Рахунки, кошики, транзакції, мультивалютність (frankfurter.dev, кеш у базі), спліт доходу, фонди подій, дашборд «Всі / Чиста база». Готово, коли: витрата записується за ≤ 3 тапи, дохід 500 € розкладається за правилом, суми сходяться до цента.
5. **CRM та інтеграції.** Контакти, угоди, інвойси (PDF), зв'язки між модулями, зовнішній сервіс через API (спочатку лише читання). Готово, коли: оплачений інвойс створює транзакцію і закриває задачу.
6. **Шліфування.** Експорт CSV/JSON, резервний вхід через email, бекапи, AI-асистент. Готово, коли: усі дані вивантажуються одним натисканням і вхід працює без Telegram.

## Безпека

- initData перевіряється на сервері (HMAC + свіжість підпису).
- Доступ лише через членство в просторі; тести ізоляції на кожну таблицю.
- Секрети тільки в змінних середовища (`.env` у `.gitignore`, опис у `.env.example`).
- Не зберігаємо номери карток і реквізити банківських рахунків.
- «Вивантажити все» і «Видалити акаунт»; щоденний бекап бази.

## Ризики

| Ризик | Як зменшити |
|---|---|
| Розрост обсягу | одна фаза за раз; CRM лише після фінансів |
| Витік даних між користувачами | тести ізоляції на кожну таблицю |
| Залежність від Telegram | внутрішній ID, резервний вхід, експорт |
| Курси валют | зберігати курс на дату операції, не перераховувати заднім числом |
